# #424 — Empty 404 page, ignored ?try link, and www not resolving

## Issue

#424 (`bug`, `ready-for-agent`). Three gaps at the edges of the site: unknown
URLs return an empty 404, a `?try=N` link does nothing visible for a coach who
already has a team, and `www.benchcard.app` does not resolve.

## Goal

- A coach who mistypes a URL or follows a dead link sees a Benchcard page that
  says the page is not here and gets them home or to a chart page.
- A coach with a team who taps "Try it with N sample players" on a chart page
  is told why nothing changed, and the address bar is clean.
- Someone who types `www.benchcard.app` lands on `benchcard.app`, same path.

## Survey

Every claim in the issue held:

- `curl -sI https://benchcard.app/nope` returns `404` with no content type;
  `app/` has no `404.html`; `wrangler.jsonc` sets
  `not_found_handling: "404-page"`.
- `app/onboarding.js` (end of `initOnboarding`) reads `?try` and strips it only
  inside `if (want !== null && !state.onboarded)`.
- `dig +short www.benchcard.app` prints nothing (no record). The apex resolves.

Found along the way:

- The service worker sends any navigation it has not precached to the network
  while online, so an unknown path reaches Cloudflare's 404 page; offline it
  gets the app shell, which is right and unchanged.
- `scripts/serve.mjs` answers a missing file with `404 text/plain "not found"`,
  so it does not match production's 404 page.
- `src/index.js` already ends with `return env.ASSETS.fetch(req)`. But the
  asset layer answers every asset request **before** the Worker runs, so a
  www custom domain on this Worker would serve every page on www as a
  duplicate (and as a separate origin with its own localStorage, so a coach
  on www would see an empty app). The Worker only sees every request when
  `assets.run_worker_first` is `true`. Its patterns are paths, not hosts, so
  it has to be `true`.
- Wrangler's custom-domain publish (`publishCustomDomains`, wrangler 4.15x)
  sends `override_scope: true` with `replace_state=true`: once `routes` lists
  any custom domain, the list **replaces** the Worker's domains. So `routes`
  must list the apex too, or the next deploy would detach `benchcard.app`.
  In CI (no TTY) it also sets `override_existing_dns_record: true`, so it
  creates the www DNS record itself.

## Decisions the issue left open

- **www is done from the repo**, not the dashboard. The issue prefers the repo
  if assets on www do not become duplicates; `run_worker_first: true` gives
  that. Trade-off, stated in the PR: every request now runs the Worker (more
  Worker invocations and Workers Logs lines; the site's traffic is far under
  the free tier). The PR lists a post-merge dashboard check and the fallback.
- **The redirect keeps the query string too.** "Keeping the path" is the
  ask; dropping `?try=7` from a www link would break it for no reason.
- **No "add a sample team" path exists for a coach with a team.** "Fill with a
  sample team" is never offered in add-team mode (`onboarding.js`, #146 item
  6). So the toast just says so, per the issue's fallback.
- **The 404 page links by root-relative hrefs** (`/`, `/7-player-…`), and its
  stylesheet too: it is served at any depth (`/a/b/c`), where `./` would
  resolve wrong.

## What would settle it

1. `build(app, dist)` puts `404.html` in `dist/`, byte-identical to
   `app/404.html`; `parsePrecache(app/sw.js)` does not include `./404.html`.
2. `serve()` answers `GET /nope` (and `/ABOUT`,
   `/13-player-basketball-rotation-chart`) with status `404`,
   `content-type: text/html; charset=utf-8`, and the bytes of `app/404.html`.
   Known pages still answer 200 as today.
3. `app/404.html`: one line of copy, exactly `This page isn't here.`, a link
   to home (`/`) and links to the six chart pages
   (`/7-player-basketball-rotation-chart` … `/12-…`). `<title>Page not found
   | Benchcard</title>`, `<meta name="robots" content="noindex">`, no
   canonical tag, not in `app/sitemap.xml`. Same look as the other static
   pages (shared tokens, light and dark). Every existing whole-tree guard over
   `app/*.html` stays green with it in place.
4. A returning coach (a saved team) opening `/?try=7` sees the toast
   `You already have a team, so the sample team wasn't loaded.`, the address
   is `/` with no `?try`, and the roster is still theirs. A first-run coach
   opening `/?try=7` still gets the sample team, as today.
5. The Worker, for a request to `https://www.benchcard.app/<path>?<query>`,
   answers `301` with `Location: https://benchcard.app/<path>?<query>` and
   never calls `ASSETS`. Requests to `benchcard.app` and any other host (the
   `*.workers.dev` preview) behave exactly as today (`/e` beacon, everything
   else to `ASSETS`).
6. `wrangler.jsonc` has `assets.run_worker_first: true` and `routes` listing
   exactly `{ "pattern": "benchcard.app", "custom_domain": true }` and
   `{ "pattern": "www.benchcard.app", "custom_domain": true }`.
7. On the branch preview: `/nope` returns 404 with the page; `/` and `/about`
   still carry the `_headers` security headers and `no-cache` (proves assets
   still flow through `env.ASSETS.fetch` with `run_worker_first`).
8. Look check of the 404 page at 320 and 390 wide, 16 and 32px text: nothing
   clipped, no sideways scroll, every link a 48px target.

## Surfaces

Change: `app/404.html` (new), `app/onboarding.js` (the `?try` block only),
`src/index.js`, `wrangler.jsonc`, `scripts/serve.mjs` (miss -> 404.html),
`scripts/smoke/static.mjs` (add the page to the static pages pass), tests
(`test/build.test.js`, `test/worker.test.js`, a Coach scenario file,
`test/coach.js` if a verb is needed), docs that name what changed.

Must not change: `app/sw.js` (404.html stays out of `PRECACHE`), the four pure
modules, `state.js`, `live.js`, `app/sitemap.xml`.

## Constraints

- **Reuse, do not re-derive:** the toast is `flash()` from `app/toast.js`.
  The Worker test drives the real `src/index.js` default export the way
  `test/worker.test.js` already does. `serve()` reuses `served()` for the 404
  body. The 404 page reuses `tokens.css` and the static pages' existing
  styles and pre-paint theme resolver rather than new CSS where it can.
- **`?try` is not a URL share** (the comment above the block, A35): the new
  branch only strips and says so; it never reads anything else from the URL.
- **Privacy claim** (AGENTS.md § Rules): if the page carries the trust line,
  use the canonical wording; it does not need to.
- **Mobile first**: verify at 390x844 first. Interface guidelines § Touch and
  input (48px targets) and § Words (plain, short copy) apply.
- **American spelling.** Stage explicit paths. No commit trailers.
- `run_worker_first` changes nothing for `/e`; the Worker comment saying the
  asset layer answers first must be updated, not left wrong.

## Design

- `app/404.html`: modeled on the shortest existing static page (`advanced.html`
  / a chart page head): theme resolver, `tokens.css` and the page styles,
  a heading or line `This page isn't here.`, a primary link `Open Benchcard`
  to `/`, then a short list of the six chart pages by name.
- `scripts/serve.mjs`: when the file is missing, answer `404` with
  `404.html`'s bytes as `text/html; charset=utf-8` (fall back to the old plain
  text if `404.html` itself is missing, for doctored test copies).
- `app/onboarding.js`: when `want !== null` and the coach is onboarded, strip
  `?try` the same way and `flash()` the copy above.
- `src/index.js`: first thing in `fetch`, if `url.hostname ===
  'www.benchcard.app'`, return `Response.redirect('https://benchcard.app' +
  url.pathname + url.search, 301)`.
- `wrangler.jsonc`: `run_worker_first: true` inside `assets`, top-level
  `routes` as in item 6, each with a comment saying why (the replace-scope
  behavior, the duplicate-origin problem).

## Proof

- `node --test test/build.test.js`: items 1 and 2 (build output, PRECACHE,
  `serve()` 404 answers).
- `node --test test/worker.test.js`: item 5, through the Worker's default
  export with a stub `ASSETS`. Item 6 as a guard in the same file that parses
  `wrangler.jsonc` (comments stripped, as `build.test.js` already reads it),
  built under `/new-guard` (watch it fail against the current file).
- Coach scenario (`test/*-scenarios.test.js`, through `test/coach.js`):
  item 4, both arms. A verb that opens the app at a URL with the saved record
  kept, and a way to read the current address, get added to `test/coach.js`
  if none fits.
- Smoke static pass (`scripts/smoke/static.mjs`): item 3's layout half and
  item 8 at 320/390 and 32px.
- `/browser-verify` on the preview: item 7, plus item 8 by `look.mjs`.

## Out of scope

- Any Cloudflare dashboard or DNS change by hand.
- A sample team for a coach who already has one.
- Redirecting `http://` (the `.app` TLD is HSTS-preloaded; the apex already
  redirects).
